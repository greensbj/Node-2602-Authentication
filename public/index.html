Node 2602 Exam on Authentication

A minimal front end for the endpoints. The access token is kept in memory; the refresh token lives in an httpOnly cookie.

Register

POST /api/auth/register — rate limited to 20 per 15 min

2 to 60 characters. Leading and trailing spaces are trimmed. Must be a valid address and not already registered. Stored lowercase — You@Ex.com and you@ex.com are the same account.
  • At least 8 characters
  • One lowercase letter
  • One uppercase letter
  • One number
Hashed with bcrypt before it is stored. It is never returned by any endpoint.

Login

POST /api/auth/login

An unknown email returns the same error as a wrong password, so the API cannot be used to discover who has an account. 5 wrong attempts locks the account. The lock clears after LOCK_TIME_MS in .env — set to 5 seconds here so it can be demonstrated; 15 minutes in production.

Session

No input needed — these use the token held in memory.

Get me sends the access token in an Authorization: Bearer header. Refresh sends no token at all — it uses the httpOnly cookie, and rotates it.
List users returns 403 unless your role is admin. To promote yourself:
db.users.updateOne({email:"test@example.com"},{$set:{role:"admin"}})
No access token

OTP verification

POST /api/auth/send-otp then /api/auth/verify-otp

Must be a registered, not-yet-verified account. Sending to an unknown email returns the same success message, so the endpoint cannot be used to find out who has signed up. One code per 60 seconds. In development the code is returned in the response and printed to the server console; in production it would only be emailed. Digits only, 4 to 8 characters. Expires 5 minutes after it is sent, and 5 wrong guesses destroy the code so a new one must be requested.

Change password

PATCH /api/auth/change-password — needs a valid access token

Checked with bcrypt before anything changes. Wrong value returns 401.
  • At least 8 characters
  • One lowercase letter
  • One uppercase letter
  • One number
Must differ from the current one. On success every session ends — including this one — so you will need to log in again.
